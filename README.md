# TeamStock — 현장 재고관리 + 직원 소통

PySide6로 만든 데스크톱 앱. 창고 재고를 배치도 기반으로 관리하고, 같은 사무실(LAN) 안에서
소켓(socket) 기반 실시간 채팅으로 직원들과 소통합니다.

## 실행

```bash
pip install -r requirements.txt
python main.py
```

첫 실행 시 `data/` 폴더와 JSON 3종(member/stock/board)이 자동 생성됩니다.

### 시연 계정

| ID | PW | 등급 |
|---|---|---|
| admin | admin123 | A 관리자 (전체 + 특수브라켓 + 승인 + 초대코드) |
| stocker | stocker123 | B 자재담당 (일반품목 입출고) |
| employee | employee123 | C 일반직원 (조회 + 출고요청) |

### 채팅 사용법 (소켓)

1. admin 로그인 → 채팅 탭 → **[서버 시작]** → **[연결]**
2. 다른 계정/PC: 서버 IP(관리자 PC) 입력 → **[연결]**
3. 전체 / 공지(admin만) / 귓속말 모드로 전송

## 기술 스택

- Python 3.12, PySide6 (GUI)
- `socket` + `threading` 기반 자체 채팅 서버/클라이언트 (TCP)
- OpenCV(선택) — 재고 촬영용, 없어도 전체 기능 동작
- 데이터 저장: JSON (로컬 파일 기반)

## 구현된 기능

- 로그인 / 초대코드 기반 가입 / 계정 잠금
- 창고 배치도 기반 재고 검색, 선입선출(FIFO) 정렬
- 출고 요청(QDialog) / 입고 승인
- 소켓 기반 실시간 채팅 — 전체 / 공지(admin 전용) / 귓속말(DM), 접속자 목록
- 게시판 (상태 3단계)
- 재고 부족 알림 (뱃지)
- 반납, 특수브라켓 잔여 사유서 (간이 구현)

## 미구현

## 소켓 채팅 설계 노트 (TCP 스트림 처리)

TCP는 "메시지 경계"가 없는 바이트 스트림이라, 보낸 쪽이 `send`를 몇 번 나눠 불렀는지와
받는 쪽이 `recv`를 몇 번 호출하는지가 서로 무관합니다. 이 프로젝트는 이 문제를
**줄바꿈(`\n`) 구분 프레이밍**으로 해결합니다:

```python
buf += data.decode()
while "\n" in buf:
    line, buf = buf.split("\n", 1)   # 완성된 메시지 한 줄만 꺼내 처리
    msg = json.loads(line)
```

또한 클라이언트 쪽에서는 `recv()`가 블로킹 호출이라는 점을 고려해, 수신을 별도 스레드로
돌리고 **Qt `Signal`을 통해 메인(UI) 스레드로 안전하게 전달**합니다 (다른 스레드에서 직접
UI를 건드리면 안 된다는 Qt 규칙을 지킨 설계).

## 학습 팁 — 단독 테스트

각 파일 하단에 `# ── 단독 테스트 (학습용)` 블록이 주석 처리되어 있습니다. 주석을 풀고 그
파일만 실행하면 해당 파트만 따로 테스트할 수 있습니다.

```bash
python stock_logic.py     # 선입선출 정렬만 확인
python storage_map.py     # 창고 배치도 화면만 띄우기
python chat_screen.py     # 채팅 창 2개 띄워 서로 대화
```
